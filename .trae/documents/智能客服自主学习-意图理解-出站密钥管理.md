# 智能客服强化：自主学习 + 意图理解 + 后台出站模型密钥管理

## Context

智能客服当前已有知识库问答（本地 JSON + `t_support_learning_candidate` 审核后发布）、意图识别（`IntentUnderstandingService` 7 类本地规则）、外部模型寒暄润色（DeepSeek/Mimosa，仅限备用链路 GREETING）。用户要求三项强化：

1. **自主学习**：未命中知识库的提问自动生成待审核候选（不自动发布，保持人工审核流）
2. **意图理解**：本地为主细分增强 + 外部模型可选辅助（只输出意图标签、不生成回答，遵守"知识问答仅走本地知识库"硬约束）
3. **后台 API 密钥接口**：管理员后台配置/更换**出站**模型密钥（DeepSeek/Mimosa 的 API Key、Base URL），运行时生效、脱敏回显

关键现状（已核实）：
- `ExternalGreetingClient` 用 `@Value` 硬读 yml 密钥，改配置需重启
- `t_support_learning_candidate` 的 `conversation_id/source_*_message_id` 均 NOT NULL，仅支持人工从会话创建
- 入站 API 密钥管理（`AiApiKeyController` + `t_ai_api_key`）已存在但**无前端页面**（本次可选补齐）
- 硬约束：知识问答仅走本地知识库、外部模型仅限寒暄润色、违规调用必须被 `FallbackPolicyGuard` 拦截

## 实施方案

### 批次 1：出站模型密钥后台管理（DB + 后端 + ExternalGreetingClient 运行时化）

**DB**（`CustomerCommunicationSchemaInitializer` 增量建表）：
```sql
CREATE TABLE IF NOT EXISTS t_outbound_model_config (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  channel VARCHAR(20) NOT NULL,            -- deepseek / mimosa
  base_url VARCHAR(200) NOT NULL,
  api_key_cipher TEXT NOT NULL,            -- AES-GCM 加密存储（可逆）
  api_key_prefix VARCHAR(16) NOT NULL,     -- 脱敏回显（如 sk-abc****）
  enabled TINYINT NOT NULL DEFAULT 1,
  updated_by BIGINT NULL, updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY ux_outbound_channel (channel)
)
```
- 密钥加密主密钥取环境变量 `OUTBOUND_KEY_SECRET`（缺省时退化用 yml 配置值）
- **回显接口只返回 api_key_prefix，绝不回传明文**；写入时 apiKey 为空 = 保留旧值

**后端**：
- 新建 `support/OutboundModelConfigService.java`：`list()`（脱敏）、`upsert(channel, baseUrl, apiKey, userId, request)`、`Optional<ChannelConfig> activeChannel(channel)`（解密返回给客户端用）、`toggle(key)`/`setToggle(key, on)`（存配置，含 `intent_external_enabled`）。全部写 `AuditService.record`（记录更新动作但不含密钥）
- 新建 `controller/OutboundModelConfigController.java`：`GET/POST /admin/outbound-model-config`、`POST /admin/outbound-model-config/toggle`，均 `@RequirePerm("admin:all")`
- 改 `ExternalGreetingClient.java`：删 4 个 `@Value`，注入 `OutboundModelConfigService`，`callChannel()` 运行时取启用渠道逐个尝试（DeepSeek 优先）；`polishGreeting` 的 `FallbackPolicyGuard` 双重校验**不动**

### 批次 2：自动学习候选

**DB**（幂等 ALTER + 唯一键）：`t_support_learning_candidate` 的 `conversation_id/source_question_message_id/source_answer_message_id` 改 NULL；新增 `source VARCHAR(16) DEFAULT 'manual'`（manual/auto）、`question_hash CHAR(64)`（NFKC+去空白后 SHA-256）+ `UNIQUE KEY ux_candidate_qhash (question_hash, status)`（仅 pending 去重，驳回后可再生成）

**后端**：
- `CustomerCommunicationService` 新增 `createAutoCandidate(question, intent)`：entry_id 自动生成 `auto-<hash前缀>`、keywords 取命中关键词、answer_text 留空待审；插入前按 question_hash+pending 去重（冲突返回已有 id）
- `SupportController`：`answers.answer()` 返回后，`matchedEntryId()==null && isEligibleForKnowledgeLearning() && 意图非 PROHIBITED` 时异步调 `createAutoCandidate`（try-catch 吞异常，不影响回答主链路）

### 批次 3：意图理解增强

- `IntentUnderstandingService` 规则补充细分（物流、退款、支付、售后等缺失类别）；`analyze()` 增强：`toggle("intent_external_enabled")` 开启时调新 `ExternalIntentClient.classify(question)`，失败/非法标签回退本地；每次写新表 `t_support_intent_log`（question_hash/intent/source/created_at）供统计
- 新建 `support/ExternalIntentClient.java`：**固定 system 提示词"只输出预定义意图标签之一"**，输出白名单校验（非白名单→回退本地），`FallbackPolicyGuard` 新增 `authorizeExternalIntent()` 仅允许 KNOWLEDGE/GREETING 意图且开关开启，**绝不生成回答文本**（同 ExternalGreetingClient 防反代设计，无自由 prompt 入口）
- 意图统计端点：`GET /admin/support/intent-stats`（`@RequirePerm`）

### 批次 4：前端 + 收尾

1. 新页面 `frontend/src/views/admin/OutboundModelConfig.vue`：渠道卡片（DeepSeek/Mimosa）填 Base URL + API Key（占位显示 `sk-abc****` 不回显）、启用开关、意图外部增强开关；注册路由 `/admin/outbound-model-config`（参考 `router/index.js` 既有 admin 路由模式）
2. `CustomerCommunicationLearning.vue` 加"来源（自动/人工）"列；审核页自动候选 answer_text 为空时**强制填写才能发布**（`CustomerCommunicationLearningReview.vue` 校验）
3. （可选补齐）`AiApiKeys.vue` 入站密钥管理页（列表/创建后一次性显示明文/禁用）
4. 安全回归：全量 `mvn test` + 手测三项约束（本地出答案、违规请求被 Guard 拦截、备用态切换自动禁外部）

## 安全要点

- 明文密钥仅写入时接收一次，其后只出 prefix；AES-GCM 加密 + 独立 secret；审计不含密钥
- 全部新端点 `@RequirePerm("admin:all")`
- 外部意图/寒暄调用均无自由 prompt 入口 + `FallbackPolicyGuard` 双重校验 + 输出白名单
- `/support/ask` 对外行为不变，本地知识库仍是回答唯一来源

## 测试（Mockito，仿 SupportAnswerServiceTest/FallbackPolicyGuardTest）

- `OutboundModelConfigServiceTest`：加解密往返、回显脱敏（断言不含明文）、空值不覆盖旧密钥、审计调用
- `ExternalGreetingClientTest`：运行时读配置（改库后即时生效）、渠道降级、Guard 拒绝非 GREETING
- `SupportAnswerServiceAutoCandidateTest`：未命中+eligible→建候选、hash 去重、命中/PROHIBITED 不建、异常不影响 answer
- `IntentUnderstandingServiceTest`（扩）：新增细分意图、外部开关关→纯本地、非法标签回退、日志写入
- `ExternalIntentClientTest`：输出白名单、失败返回 null、不产出回答文本

## 验证方式

1. `mvn -f backend\pom.xml test` 全量通过（当前基线 316）
2. 后台改密钥 → `POST /support/fallback/status` 渠道状态即时变化（无需重启）；接口回显无明文
3. `/support/ask` 问未命中问题 → 学习候选审核页出现 pending 自动候选；重复问不产生第二条
4. 意图开关切换 → 外部调用计数变化、失败回退本地；`/support/intent/analyze` 返回细分意图
5. 手测硬约束：知识问答仍只走本地、违规（反代/注入）请求被 Guard 拦截、主服务恢复自动切回
6. `cd frontend && npx vitest run` + `npx vite build` 通过
