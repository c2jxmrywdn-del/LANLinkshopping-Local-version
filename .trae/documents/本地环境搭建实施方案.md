# LANLinkShopping 本地环境搭建实施方案

## Context（背景与目标）

本项目是「LANLinkshopping 聚合型电商」毕业设计（Spring Boot 3.5.3 + MyBatis-Plus + MySQL 8 + Vue3/Vite/Ant Design Vue），当前配置面向生产部署（Railway 后端 + Vercel 前端 + 云 MySQL），本地无法直接跑通：数据库口令靠外部环境变量、邮件/支付/客服沙盒指向外部服务、Session Cookie 为跨站生产策略。目标：把所有外部依赖改成本地可运行配置，验证前后端完整业务流程，并产出可一键复现的《本地环境运行说明 + 配置修改清单》。

## 一、架构梳理结论（已调研完成，将写入运行说明）

**真实应用 = `backend/`（Spring Boot）+ `frontend/`（Vue3），单体 MySQL 依赖，无 Redis/MQ（compose.yaml 与根 pom.xml 是 Spring Initializr 脚手架残留，不参与运行）。**

- 后端（backend/src/main/java/com/lanlink/shopping）：
  - `config/`：WebConfig（CORS `app.cors.allowed-origin-patterns`、拦截器链、uploads 静态映射）、AuthInterceptor（Session 登录态 + RBAC）、PermInterceptor、CsrfInterceptor、AuthRateLimitInterceptor（内存令牌桶，无 Redis）、UserContext、DataInitializer（演示数据）、InfraConfig（内存缓存）。
  - `controller/`：Auth、Home、Product、Merchant、Cart、Order、User、Admin*(审核/配置/营销邮件/客服学习)、SupportLearningSandboxController（代理调 Docker 沙盒）等。
  - `service/`：OrderService（`checkout()` 事务：校验库存→订单+明细快照→扣库存加销量→清购物车→发 Spring 事件）、MerchantService.applyScreening（公司或个体户注资>10万且纳税稳定→通过）、VerifyCodeService（验证码：SMTP/Resend/AgentLoadout 三通道 + demo 回显）、PaymentService（mock=true 全本地流程）、MarketingEmailUnsubscribeService（默认公网地址需本地覆盖）。
  - 认证：HttpSession 存 LOGIN_USER；CSRF 双提交令牌（`/user/csrf-token` → `X-CSRF-TOKEN` 头）；前端 axios `withCredentials:true`，经 Vite `/api` 代理同源访问。
- 前端（frontend/src）：`api/request.js`（baseURL `/api` + CSRF 拦截器）、`api/index.js`（全部 REST 调用）、`router/index.js`（meta.auth/admin/perms 守卫）、`store/`（Pinia：user 存 `localStorage.ll_user`、cart）、`views/`（登录、商户入驻、商品、购物车、订单支付、admin 后台）。开发端口 5173，代理到 8080。
- 数据库：`backend/src/main/resources/sql/schema.sql`（建库 11 表 + 字典）+ `account.sql`，dev profile `spring.sql.init.mode: always` 幂等执行；演示数据由 DataInitializer 注入。
- 可选外部组件（用户已确认全部纳入）：Mailpit 本地邮件（SMTP:1025 + 收件箱 UI:8081）、支付宝沙箱（密钥占位符，默认 mock）、support-learning-sandbox（Docker，127.0.0.1:18080，经 SUPPORT_SANDBOX_URL/TOKEN 调用）。

## 二、实施步骤

### 1. 配置本地化（修改/新增文件）

1. **`backend/src/main/resources/application-dev.yml`**（本地 dev 覆盖）：
   - Session Cookie 改为本地安全策略：`server.servlet.session.cookie.secure: false`、`same-site: lax`（现有 `secure:true + same-site:none` 为 Vercel/Railway 跨站设计，本地 HTTP 会掉登录态）。
   - 本地邮件指向 Mailpit：`spring.mail.host: localhost`、`port: 1025`、`username/password` 任意非空（Mailpit 免认证收信），并设 `MAIL_SMTP_SSL=false` 语义（`mail.smtp.ssl.enable: false`）。
   - `lanlink.verify-code.demo-mode: true` 保留（验证码回显兜底），`LANLINK_PUBLIC_API_URL` 默认值覆盖为 `http://localhost:8080/api`（MarketingEmailUnsubscribeService 的退订链接现在默认指 Railway 公网地址）。
2. **新建 `backend/src/main/resources/application-payment.yml`**（已 gitignore）：从 `application-payment.yml.example` 复制，`mock: true`、`notify-base-url: http://localhost:8080/api`，支付宝 `gateway-url` 改为沙箱 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，app-id/private-key/公钥留空占位并注释说明获取方式；微信渠道留空。
3. **新建 `docker-compose.local.yml`**（项目根，替代脚手架 compose.yaml 的本地基建角色）：
   - `mailpit`：axllent/mailpit，映射 `1025:1025`（SMTP）、`8081:8080`（收件箱 UI）。
   - `support-learning-sandbox`：build `./support-learning-sandbox`，映射 `127.0.0.1:18080:8080`，`SUPPORT_SANDBOX_TOKEN` 用 .env 注入。
   - **新建 `.env.example`**：`SPRING_DATASOURCE_PASSWORD`、`SUPPORT_SANDBOX_TOKEN` 等本地变量模板（真实 .env 不入库）。
4. **更新 `启动前后端.bat`**（或新增 `启动本地环境.bat`）：把 Mailpit/沙盒的 docker compose up、后端 dev profile 启动（带 SPRING_DATASOURCE_PASSWORD=root密码 等本地环境变量）、前端 npm run dev 串成一键脚本；数据库沿用本机 MYSQL8.0 服务（用户已确认，root 密码按用户提供的 `Root666.` 配置，仅写入本地 .env/脚本，不提交）。
5. **新建运行说明文档 `docs/本地环境运行说明.md`**：包含①架构与模块调用关系 ②接口传参规范（统一 R 包装 `{code,message,data}`、CSRF、Session）③核心数据对象（11 表 + DTO/VO）④关键业务逻辑（下单事务、商户筛选、验证码、mock 支付）⑤一键启动步骤 ⑥演示账号 ⑦**配置修改项清单**（逐项：文件/键/原值/新值/原因）⑧常见问题。

### 2. 环境搭建与验证（按序执行）

1. 启动 Docker Desktop → `docker compose -f docker-compose.local.yml up -d`（Mailpit + 沙盒），确认 `localhost:8081` 收件箱与 `127.0.0.1:18080/health` 可用。
2. `mvn -f backend/pom.xml package` 编译 → 以 dev profile 启动后端（本机 MySQL 8.0，`lanlink_shopping` 库自动建库建表），确认 11 表 + 字典 + 演示数据。
3. 接口验证（curl）：`GET /api/home/industries`、`GET /api/product/page`、`POST /api/auth/login`（演示账号 123456）→ 携 CSRF 加购 → `POST /api/order/checkout` → `POST /api/order/pay/{no}`（mock 支付全链路）→ `GET /api/order/my` 核对。
4. 邮件链路：触发注册/改邮箱验证码 → Mailpit 收件箱确认收到真实 SMTP 邮件（demo 回显仍可用）。
5. 沙盒链路：admin 调 `/api/admin/support-learning/evaluate` 确认容器评估返回。
6. 前端：`npm install` + `npm run dev` → 浏览器走通：登录 → 商品浏览 → 加购 → 下单 → 支付 → 订单列表；admin 后台（footer 连点 10 次入口）核对商户审核。
7. 回归检查：`mvn -f backend/pom.xml test`（如有测试）。

### 3. 交付物

- `docs/本地环境运行说明.md`（含配置修改清单）— 主交付
- `docker-compose.local.yml`、`.env.example`、本地化后的 `application-dev.yml`、`application-payment.yml`、一键启动脚本
- 最终回复中给出架构梳理摘要 + 配置清单摘要 + 验证结果

## 三、验证标准

- 后端 `http://localhost:8080/api` 健康检查 200，11 表就绪；
- 核心流程接口全通：登录 → 加购 → 结算 → mock 支付 → 订单可查（curl + 浏览器双重验证）；
- Mailpit 收到验证码邮件；沙盒容器接口返回评估结果；
- 前端 5173 页面全流程无 401/CSRF/跨域报错（浏览器控制台干净）；
- 按运行说明从零可复现（配置清单完整可对照）。
