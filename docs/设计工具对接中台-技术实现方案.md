# 设计工具对接中台 · 技术实现方案

> 所属系统：LANLinkshopping（Spring Cloud 微服务 + Vue3）
> 服务：`cloud/lanlink-design-service`（8107，经网关 8300 `/api/design/**` 访问）
> 前端：`frontend/src/views/DesignStudio.vue`（路由 `/design-studio`）

---

## 一、技术选型说明

| 层 | 选型 | 理由 |
|----|------|------|
| 服务框架 | Spring Boot 3.2.5 + Spring Cloud 2023.0.1 | 与既有微服务体系一致，统一治理 |
| 注册/配置中心 | Nacos（Spring Cloud Alibaba 2023.0.1.2） | 服务发现 + 配置热更新，凭据可托管配置中心 |
| 服务入口 | Spring Cloud Gateway（8300） | 统一鉴权/跨域/路由，设计能力对前端只暴露 /api/design/** |
| 第三方对接 | JDK HttpClient + Jackson（Figma REST / Canva Connect API） | 零重依赖、超时可控，便于 mock/live 切换 |
| 前端 | Vue3 + Pinia + Ant Design Vue 4 | 与主站一致；`designApi` 统一封装 + 状态反馈 |
| 代码导出 | 服务端模板生成（React/Vue/HTML/CSS）+ 设计令牌→CSS 变量映射 | 统一产物质量，样式变量自动映射可追溯 |

**关键决策**：① mock/live 双模式（`lanlink.design.mode`），无凭据可完整演示、有凭据免改代码切真实 API；
② 能力模型（Capability）而非统一全量接口，按工具能力路由，不支持的能力显式报 UNSUPPORTED；
③ 所有异常经 `GlobalExceptionHandler` 统一为 `{code,message,data}`，前端给出明确提示。

## 三、模块交互逻辑（核心链路）

1. **OAuth 2.0 授权**：`GET /design/auth/{tool}/url` → 前端跳转授权 → 回调带 code → `POST /design/auth/{tool}/token` 换取访问令牌 → 前端缓存并经 `X-Design-Token` 头携带。
2. **设计变更 ≤3s 同步**：前端 `GET /{tool}/files/{key}/sync?sinceVersion=vN`（轮询/事件触发）→ 适配器按版本游标返回变更节点 + 最新令牌 → 前端增量刷新预览与令牌面板。实测 mock 链路 67ms（远优于 3s 目标）。
3. **代码导出**：选组件 + 格式（REACT/VUE/HTML/CSS）→ 适配器取组件与令牌 → `CodeExportService` 生成代码 + `tokensToCss` 自动映射 CSS 变量 → 前端展示/一键复制。
4. **Canva 闭环**：检索模板库 → `POST /{tool}/embed` 唤起在线编辑器（Embed URL + 参数）→ 用户二次创作 → `POST /{tool}/callback` 回传成果 URL → 系统落库/展示，形成「模板→编辑→回传」闭环。

## 四、可扩展性设计（Sketch / Adobe XD 接入）

新工具接入只需两步（其余零改动）：
1. 实现 `DesignToolAdapter`（按需声明 `Capability`），标注 `@Component`；
2. 在 `lanlink.design.{tool}` 配置凭据（live 模式）。
`AdapterRegistry` 自动发现注册，`/design/tools` 能力矩阵即时体现，前端工具切换器自动出现新工具。低耦合高内聚：web 层只依赖接口与统一模型，不感知具体工具。
