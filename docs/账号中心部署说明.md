# 账号中心部署说明

本模块随主工程一起构建与部署，无独立服务。以下为本模块相关的初始化、配置与验证要点。

## 1. 数据库初始化

账号中心新增表（`t_user_profile` 补齐列、`t_user_settings`、`t_user_totp`、`t_third_auth`、`t_audit_log`）位于：

```
backend/src/main/resources/sql/account.sql
```

- 与 schema.sql 幂等约定一致（CREATE TABLE IF NOT EXISTS / 条件加列，绝不 DROP），可重复执行
- 已追加进 `application-dev.yml` 的 `spring.sql.init.schema-locations`，**后端启动时自动执行**（排在 schema.sql 之后）：

```yaml
sql:
  init:
    mode: always
    encoding: UTF-8
    schema-locations: classpath:sql/schema.sql,classpath:sql/account.sql
```

- 第三方授权演示数据（买家账号 2 条：微信/支付宝）由 `DataInitializer` 在启动时按（用户+应用）幂等补种，已存在的库也会补齐，不会重复插入

## 2. 配置项

| 配置 | 位置 | 说明 |
|---|---|---|
| multipart 上传限制 | `application.yml` → `spring.servlet.multipart` | `max-file-size: 5MB`，`max-request-size: 6MB`（默认 1MB 会挡头像上传） |
| 敏感字段加密 | `lanlink.crypto.secret` | SHA-256 派生 AES-GCM 密钥；生产务必改用环境变量注入 |
| 上传目录 | 运行目录 `./uploads/avatars` | 后端自动创建；`/api/uploads/**` 静态映射对应该目录（`WebConfig.addResourceHandlers`） |

## 3. 构建

后端：

```bash
cd backend
mvn package -DskipTests        # 产物 target/lanlink-shopping.jar
```

前端：

```bash
cd frontend
npm install
npm run build                  # 产物 dist/
```

单元测试（21 项，TOTP/验证码/设置合并/密码规则）：

```bash
cd backend
mvn test                       # 报告在 target/surefire-reports/
```

## 4. 启动

- 方式一（一键脚本）：双击 `启动前后端.bat`
- 方式二（手动）：
  - 后端：`cd backend && java -jar target\lanlink-shopping.jar`（8080，上下文 /api）
  - 前端：`cd frontend && npm run dev`（5173，已代理 /api）

## 6. 功能自检清单

1. `/me`：三栏（≥1200）/ 两栏（768-1199）/ 单栏（<768）响应式
2. 个人信息：只读/编辑切换、固定保存/取消、取消弹确认、草稿 AES 加密刷新可恢复、手机号/邮箱脱敏
3. 头像：JPG/PNG/WebP 校验、≤5MB、裁剪/旋转/进度条/失败重试
4. 换绑：手机号/邮箱发验证码（演示环境接口直接回显 devCode）、换绑成功同步登录账号
5. 密码：强度规则拦截、改后新密码登录
6. TOTP：扫码启用（记录首次验证时间）→ 登出 → 登录时先密码再动态码（错误码被拒）
7. 系统设置：主题（亮/暗/跟随系统，实时生效并持久化）、语言/字号、通知分组一键开关、隐私开关与第三方授权撤回（二次确认）、恢复默认设置
8. CSRF：无令牌的非 GET /user/** 请求返回 403+CSRF 提示，前端自动换令牌重放
9. 审计：关键操作落 t_audit_log；后台/audit 查询筛选 + CSV 导出

## 7. 安全说明

- 敏感字段（profile 的 realName/phone/email 等、TOTP 密钥）AES-GCM 加密存储
- 存储周期不小于 180 天：审计日志由后台保留策略保证（演示环境不自动清理）
- 所有写操作受会话级 CSRF 令牌保护；`/admin/**` 有独立 RBAC 校验
