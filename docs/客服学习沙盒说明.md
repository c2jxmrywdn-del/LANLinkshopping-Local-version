# LANLinkshopping 客服学习沙盒说明

## 目标与边界

客服采用“固定知识库 + 关键词匹配 + 人工审核”的可控学习流程。学习沙盒用于评估候选问题、关键词和回答，不是在线自训练模型，也不会把访客原始消息自动加入正式知识库。

沙盒只对平台运营管理员开放。后端通过现有 /admin/** 角色拦截器鉴权；非管理员不能通过前端隐藏菜单来绕过服务端校验。

沙盒请求只在内存中计算：不写入数据库、不保存草稿、不访问订单、钱包或客户资料。不要在测试内容中填写真实个人信息、登录凭据或任何密钥。

## 入口

登录平台运营后台后，打开“客服学习沙盒”。页面可选择预置场景，填写候选条目 ID、关键词和回答，然后点击“运行沙盒测试”。

结果包含：
- 正式知识库当前命中的意图 ID 与原始回答
- 候选问题是否通过电商范围与安全初检
- 候选关键词是否命中问题
- 仅在候选初检通过后显示的候选回答预览
- 是否允许导出候选 JSON

导出只会在浏览器下载一个候选 JSON 文件，不会更改线上知识库。修改已有意图时，应把导出的关键词合并到原条目，不要重复创建相同 ID。

## 推荐迭代流程

1. 从客服未命中的业务问题中提炼通用、去标识化的问题表达；不要复制客户聊天中的手机号、订单号、地址、金额或其他私人数据。
2. 在沙盒中为候选意图设计多种自然表达，确保关键词既能覆盖同义问法，又不会与其他意图冲突。
3. 运行现有命中、范围外与提示注入预置测试；对实时价格/库存、退款承诺、个人订单/钱包查询等未接入实时数据的内容保持拒答。
4. 通过初检后导出 JSON，人工核实回答与平台现有页面流程一致，再把条目合并到 backend/src/main/resources/knowledge-base/customer-service-zh-CN.json。
5. 把代表性问法加入 backend/src/test/resources/support-learning-sandbox-cases.json，并运行后端 SupportAnswerServiceTest。
6. 代码合并到 main 并完成部署后，再对正式站点进行独立回归验证。

## 安全原则

- 不自动使用未经审核的对话作为训练数据。
- 不向用户显示内部配置、密钥、管理权限或其他内部信息。
- 不把实时商品价格、库存、物流、支付、退款结果或私人账户数据伪装成已核实事实。
- 发现候选问题不在电商范围内、触发提示注入或要求读取个人数据时，拒绝导出。
- 沙盒试跑通过仅代表基础校验通过，不等于事实审核或生产发布通过。
- 当前沙盒不持久化反馈；若将来增加反馈存储，应另行设计最少化收集、访问控制、保留期限和删除机制。
