# LANLinkshopping 邮件通道配置（HTTPS API / SMTP）

邮箱验证码支持两种真实投递方式：推荐使用 HTTPS 邮件 API（Resend），同时保留 SMTP。真实邮件发送成功后，API 不会把验证码回显给前端；已配置的真实通道发送失败时不会静默退回演示码。

## Railway 推荐方案：Resend HTTPS API

Railway 的 Free、Trial 和 Hobby 方案限制 SMTP 出站端口（25/465/587），官方建议使用提供 HTTPS API 的事务邮件服务。当前 Railway 日志里出现过连接 smtp.qq.com 超时；本项目的套餐等级尚未从连接状态中确认。官方说明：https://docs.railway.com/networking/outbound-networking

1. 在 Resend 或其他兼容的事务邮件服务创建 API Key，并验证一个可用于发件的域名/地址。
2. 在 Railway → LANLinkshopping → Variables 中配置：

| 变量 | 值 |
| --- | --- |
| MAIL_PROVIDER | resend |
| RESEND_API_KEY | 邮件服务生成的 API Key（只在 Railway 中填写） |
| MAIL_FROM | 例如：LANLinkshopping <noreply@your-verified-domain.com>，请替换为已验证的发件地址 |

不要将 API Key 写进代码、YAML、GitHub 或聊天消息。配置完成后重新部署。Resend 模式会通过 HTTPS 调用邮件 API，不需要 SMTP 出站端口。

## QQ / Gmail SMTP（仅限允许 SMTP 出站的部署）

如果服务所用的部署套餐允许 SMTP 出站，或后端运行在其他支持出站 SMTP 的主机，可以设置：

| 变量 | QQ 邮箱示例 |
| --- | --- |
| MAIL_PROVIDER | smtp |
| MAIL_HOST | smtp.qq.com |
| MAIL_PORT | 465 |
| MAIL_USERNAME | 完整 QQ 邮箱地址 |
| MAIL_PASSWORD | 邮箱设置中生成的 SMTP 授权码，不是网页登录密码 |
| MAIL_SMTP_SSL | true |
| MAIL_SMTP_STARTTLS | false |
| MAIL_FROM | 可选；默认使用 MAIL_USERNAME |

Gmail 常用 STARTTLS 配置为 MAIL_HOST=smtp.gmail.com、MAIL_PORT=587、MAIL_SMTP_SSL=false、MAIL_SMTP_STARTTLS=true、MAIL_SMTP_STARTTLS_REQUIRED=true，并使用应用专用密码。

## 通道选择规则

- MAIL_PROVIDER=resend：只使用 Resend HTTPS API。
- MAIL_PROVIDER=smtp：只使用 SMTP。
- MAIL_PROVIDER=auto（默认）：如果 API Key 与发件地址齐全，优先使用 HTTPS API；否则才使用完整配置的 SMTP。
- 只有在没有配置任何可用真实邮件通道时，开发 Profile 才可能返回演示验证码。
- 已配置的真实通道若发送失败，会返回错误并清除本次验证码，不会将验证码回显为演示码。
- /api/actuator/health、/api/actuator/health/liveness 和 /api/actuator/health/readiness 是应用探针；邮件服务连接不再纳入健康检查，避免 SMTP 超时影响服务探测。就绪探针包含应用状态与数据库状态。

## 生产切换提示

当前 Railway 部署沿用 dev Profile 来保留演示登录/支付流程。仅配置邮件通道不会自动切换 Profile。真实生产上线前，还需配置并验证短信与真实支付通道，再将 SPRING_PROFILES_ACTIVE 切换为 prod，同时关闭模拟支付。不要在缺少其他生产通道时提前切换，以免演示流程中断。
