# 基于用户类型的访问控制规则文档

> 版本：1.0　适用范围：LANLinkshopping 全站（前台 + 后台）
> 配套实现：后端 `common.UserIdentity`（权限矩阵）+ `integration.security.PermInterceptor`（强制校验）；
> 前端 `store/user.js hasPerm`（条件渲染）+ `router` meta.perms 守卫。

## 1. 用户身份类型（识别口径）

| 身份 code | 名称 | 识别规则 |
| --- | --- | --- |
| guest | 访客 | 未登录 |
| buyer | 普通用户 | 已登录，role_id=1（采购方） |
| vip | VIP 用户 | role_id=1 且累计已支付金额 ≥ ¥5000 |
| merchant | 商户 | role_id=2（入驻且审核通过） |
| admin | 管理员 | role_id=3（平台运营） |

识别优先级：admin > merchant > vip > buyer > guest。每次请求由 `IdentityService` 实时计算（`AuthInterceptor` 写入请求上下文）。

## 2. 权限矩阵（后端事实源）

| 权限标识 | guest | buyer | vip | merchant | admin |
| --- | :-: | :-: | :-: | :-: | :-: |
| product:view / product:search | ✅ | ✅ | ✅ | ✅ | ✅ |
| cart:manage（购物车） | — | ✅ | ✅ | ✅ | ✅ |
| order:create / order:view（下单/订单） | — | ✅ | ✅ | ✅ | ✅ |
| address:manage（收货地址） | — | ✅ | ✅ | ✅ | ✅ |
| profile:manage（个人资料/账号中心） | — | ✅ | ✅ | ✅ | ✅ |
| vip:discount / vip:service（VIP 专属） | — | — | ✅ | — | ✅ |
| merchant:manage / product:publish（商户） | — | — | — | ✅ | ✅ |
| admin:all（后台全权） | — | — | — | — | ✅ |

> admin 通过 `admin:all` 视为通配全权（后端 Admin 路由另由 AuthInterceptor 强制 role_id=3 双重校验）。

## 3. 前后端双层校验

### 3.1 后端（权威，不可绕过）
- **AuthInterceptor**（所有请求）：登录校验 + 实时身份识别 + `/admin/**` 强制 admin（role_id=3），越权返回 403 并写 `ACCESS_DENIED` 审计。
- **PermInterceptor**（所有请求，AuthInterceptor 之后）：读取 Handler 方法上的 `@RequirePerm("...")`，按当前身份权限矩阵校验；不满足 → 401（未登录）/ 403（权限不足）+ `ACCESS_DENIED` 审计日志。

已应用注解的端点：

| 端点 | 所需权限 | 说明 |
| --- | --- | --- |
| POST /product/publish | product:publish | 商户发布商品 |
| GET /product/my/list | product:publish | 商户商品列表 |
| GET /user/vip/benefits | vip:discount | VIP 专属权益（演示） |
| /admin/** | role_id=3（AuthInterceptor） | 运营后台 |

### 3.2 前端（体验层，非安全边界）
- **路由守卫**：`meta.perms` 声明所需权限（cart/checkout/orders/merchant-products/me 等），无权限访问重定向首页；`meta.auth` 未登录跳登录；`meta.admin` 非管理员静默回首页。
- **菜单动态渲染**：MainLayout 按 `hasPerm` 显示/隐藏「我的订单」「我的商品」等入口。
- **按钮条件渲染**：Mall 加购按钮（cart:manage）、ProductDetail 加购/立即购买（cart:manage/order:create），无权限显示「登录后购买」。

> 安全边界在后端；前端条件渲染仅提升体验，前端绕过不构成越权（后端强制校验兜底）。

## 5. 扩展指引

- **新增权限标识**：在 `common.UserIdentity` 对应身份的 `permissions` 列表追加；后端端点加 `@RequirePerm("新权限")`；前端路由 meta.perms / v-if 引用同名标识。
- **新增身份类型**：在 `UserIdentity` 增加枚举 + `IdentityService.identify` 分支 + 权限列表，其余自动联动。
- 权限标识保持前后端字符串一致（单一事实源为后端枚举，前端仅镜像）。
