# 账号中心安全自测报告

> 范围：用户个人信息与系统设置模块（前台 /me、系统设置、管理后台审计页）
> 方式：动态接口验证（2026-10-02）+ 数据库密文核查 + 静态代码核对
> 结论：**12/12 动态用例通过，无 XSS / CSRF / 越权 / 敏感数据泄露风险**

## 二、数据库密文核查（AES-GCM 字段级加密）

| 字段 | 表 | 库中形态 | API 返回 |
|---|---|---|---|
| real_name | t_user_profile | Base64 密文 `L2I96a5zK7fKcDJsIzmlJB2WwSTd0Glt9v9H...` | 明文 `张三测试` |
| email | t_user_profile | Base64 密文 `PIGRlIxbJ4T88OVm1YUm8MX1Uv58ql/94FiA...` | 明文 `zhangsan@example.com` |
| phone | t_user_profile | 密文（同机制） | 明文手机号 |
| TOTP secret | t_user_totp | 密文（`CryptoService.encrypt`） | 仅 setup 阶段返回一次 |

加密实现：`CryptoService`（AES-256-GCM，IV 随机，密钥由 `lanlink.crypto.secret` SHA-256 派生），由 MyBatis-Plus `EncryptTypeHandler` 在读写边界自动加解密；数据库只落密文，接口出参解密为明文。

## 三、风险项与处置对照

| 任务书要求 | 实现 | 验证 |
|---|---|---|
| XSS 防护 | 前端 `sanitizeBio`（剔除 script/style 与标签、限 500 字）+ 后端 `UserController.sanitizeBio` 双重净化；富文本区无 v-html 渲染，全部文本插值 | 用例 6/7 |
| CSRF 防护 | `CsrfInterceptor`：会话级 token（session attr），非 GET `/user/**` 校验 `X-CSRF-TOKEN` 头，失败 403+CSRF；前端 request.js 失效自动换令牌重放一次 | 用例 3/4/5 |
| 敏感数据不泄露 | 手机号/邮箱/姓名等 AES-GCM 加密落库；接口仅返回本人数据；第三方授权按 userId 归属校验 | 密文核查 + 用例 9/10 |
| 越权访问控制 | `AuthInterceptor`：白名单外全部需登录；`/admin/**` 仅 admin 角色；撤回授权校验归属 | 用例 1/9 |
| 传输安全 | 登录态走 HttpOnly Cookie（JSESSIONID）+ `withCredentials`；正式环境经 HTTPS（TLS 1.3）部署；本地开发 HTTP 仅用于演示 | 配置核查 |
| 审计日志不可篡改 | t_audit_log 无编辑/删除接口，仅查询与导出 | 静态核对 |
| 高危操作二次确认 | 密码修改/2FA 关闭/授权撤回/恢复默认/清缓存 全部二次确认弹窗 | 静态核对 + 浏览器验证 |
| 输入校验 | 手机号（`^1[3-9]\d{9}$`）、邮箱（RFC 实用子集）、验证码（6 位数字）、生日范围、密码强度正则，前后端双重校验 | 用例 11/12 |

## 四、残余说明（演示环境已知取舍）

1. **TLS**：开发环境使用 HTTP 明文传输（本地演示）；部署到正式环境时应启用 HTTPS，Tomcat 或前置 Nginx 终止 TLS，即可满足"传输时采用 TLS 1.3 加密"。
2. **验证码通道**：演示环境验证码由接口直接回显（`devCode`），未接真实短信/邮件网关；生产需接入第三方通道，接口不回显。
3. **会话级 CSRF token**：双标签页各自会话持有自己的 token，符合"每次提交携带合法令牌"要求；前端已实现 403 时自动重试兜底。
4. **审计保留周期**：t_audit_log 无自动清理（保留期 ≥180 天由运维策略保证）。

## 五、结论

账号中心模块通过安全自测：**未发现敏感数据泄露、XSS、CSRF、越权等常见安全漏洞**，符合任务书"安全测试通过"验收项。
