# 设计工具集成指南（Figma / Canva / 新工具接入）

> 适用服务：`cloud/lanlink-design-service`。默认 `mock` 模式无需任何外部凭据即可完整演示；
> 如需真实联调，按本文档申请凭据并切换 `live` 模式，代码零改动。

---

## 一、通用运行与切换

### 1.1 启动（本地）
```powershell
docker compose -f docker-compose.cloud.yml up -d      # Nacos 8848
cd cloud; .\start-dev.ps1                              # 构建并启动 gateway + 8 服务
# 设计服务健康：http://localhost:8107/actuator/health
# 经网关访问：http://localhost:8300/api/design/**
```

### 1.2 mock / live 切换
| 模式 | 配置 | 说明 |
|------|------|------|
| mock（默认） | `lanlink.design.mode=mock` | 内置演示数据，全流程可跑，无需凭据 |
| live | `lanlink.design.mode=live` + 对应工具凭据 | 真实调用 Figma/Canva API |

环境变量（或 Nacos 配置 `lanlink-design-service.yaml`）：
```yaml
lanlink:
  design:
    mode: live                       # 默认 mock
    figma:
      client-id: ${FIGMA_CLIENT_ID}
      client-secret: ${FIGMA_CLIENT_SECRET}
      redirect-uri: http://localhost:8300/api/design/auth/figma/callback
      api-base-url: https://api.figma.com
    canva:
      client-id: ${CANVA_CLIENT_ID}
      client-secret: ${CANVA_CLIENT_SECRET}
      redirect-uri: http://localhost:8300/api/design/auth/canva/callback
      api-base-url: https://api.canva.com
```

### 1.3 统一调用约定
- 所有接口经网关前缀 `/api/design/**`，业务请求需 `Authorization: Bearer <token>`（网关鉴权）；
- OAuth 授权跳转/回调 `/api/design/auth/**` 为公开路径；
- 设计令牌经 `X-Design-Token: <oauth access_token>` 头传递；
- 响应统一 `{code, message, data, success}`，`code=200` 成功，异常为友好中文提示。

## 二、Figma 集成（live）

### 2.1 申请凭据
1. 登录 [Figma Developers](https://www.figma.com/developers) → 创建 App（OAuth 2.0）；
2. 记录 **Client ID / Client Secret**；配置 **Redirect URL** 为 `http://localhost:8300/api/design/auth/figma/callback`（生产改线上域名）；
3. 申请 scope：`file_read`（读取设计文件/样式）。

### 2.2 对接接口（适配器已实现）
| 步骤 | 接口 | Figma API |
|------|------|-----------|
| 获取授权地址 | `GET /design/auth/figma/url?state=xxx` | `https://www.figma.com/oauth?...` |
| 令牌交换 | `POST /design/auth/figma/token` `{code}` | `POST /oauth/token (authorization_code)` |
| 令牌刷新 | `POST /design/auth/figma/refresh` `{refreshToken}` | `POST /oauth/token (refresh_token)` |
| 读取设计文件 | `GET /design/figma/files/{fileKey}` | `GET /v1/files/{key}` |
| 批量组件导出 | `POST /design/figma/files/{key}/components` | `GET /v1/images/{key}?ids=...` |
| 设计令牌解析 | `GET /design/figma/files/{key}/tokens` | `GET /v1/files/{key}/styles` |
| 实时预览 | `GET /design/figma/files/{key}/preview?nodeId=` | `GET /v1/images/{key}` |
| 增量同步（≤3s） | `GET /design/figma/files/{key}/sync?sinceVersion=` | 版本游标 diff nodes |

### 2.3 注意事项
- Figma PAT（Personal Access Token）也可直接作 `X-Design-Token` 跳过 OAuth（内部工具场景）；
- rate limit：Figma 对 `/v1/images` 有并发限制，建议服务端缓存导出 URL（本实现返回 URL 由前端直连 Figma CDN）；
- 预览图建议前端 3s 轮询 `sync` 接口判断 `hasChanges` 再刷新预览，避免无效渲染。

## 三、Canva 集成（live）

### 3.1 申请凭据
1. 注册 [Canva Developers](https://www.canva.dev/) → 创建 App（Canva Connect API）；
2. 记录 **Client ID / Client Secret**；配置 **Redirect URL** 为 `http://localhost:8300/api/design/auth/canva/callback`；
3. 申请 scope：`design:content:read`、`design:content:write`、`asset:read`、`asset:write`；
4. 如需 Embed 在线编辑器，启用 **Canva Connect Embed SDK**（编辑器嵌入需 Canva 企业/开发者计划支持）。

### 3.2 对接接口（适配器已实现）
| 步骤 | 接口 | Canva API |
|------|------|-----------|
| 模板库检索 | `POST /design/canva/templates` `{keyword, category, style}` | `GET /v1/templates` |
| 唤起在线编辑器 | `POST /design/canva/embed` `{designId}` | `POST /v1/designs` + Embed URL |
| 成果回传闭环 | `POST /design/canva/callback` `{designId, exportUrl}` | `POST /v1/exports` 取成品 URL |
| 令牌交换/刷新 | `/design/auth/canva/token`、`/refresh` | `POST /oauth/token` |

### 3.3 前端嵌入示例（Embed SDK）
```html
<iframe :src="embedSpec.embedUrl"
        :width="embedSpec.width" :height="embedSpec.height"
        allow="fullscreen" referrerpolicy="no-referrer"></iframe>
```
编辑完成后由 Canva 回调/前端捕获成品 URL，调用 `callback` 接口回传系统完成闭环。

## 四、接入新设计工具（Sketch / Adobe XD / MasterGo）

1. **实现适配器**（示例骨架）：
```java
@Component
public class SketchAdapter implements DesignToolAdapter {
    @Override public String toolId() { return "sketch"; }
    @Override public String displayName() { return "Sketch"; }
    @Override public Set<Capability> capabilities() {
        return EnumSet.of(Capability.FILE_READ, Capability.COMPONENT_EXPORT,
                Capability.TOKEN_PARSE, Capability.PREVIEW);
    }
    // 按需实现 buildAuthUrl/exchangeToken/... 支持的接口
    // 不支持的能力可继承默认实现抛 UNSUPPORTED，或不声明该 Capability
}
```
2. **配置凭据**：`application.yml` 或 Nacos 增加 `lanlink.design.sketch.*`；
3. **零改动验证**：`GET /design/tools` 能力矩阵自动出现 Sketch；前端工具切换器自动出现；
4. 统一数据模型（`DesignModels`）保证前端无需为新工具改代码。

## 五、常见问题
1. **401 缺少访问令牌**：业务接口需 `X-Design-Token`；mock 模式先走 `/design/auth/mock/token` 用演示码换取。
2. **live 模式 404/403**：检查 client-id/secret、redirect-uri 与后台配置一致，scope 是否齐备。
3. **增量同步超 3s**：live 模式受第三方 API 影响，建议配置本地缓存（版本游标 + 变更节点缓存）；mock 链路实测 67ms。
4. **导出格式报错**：仅支持 REACT/VUE/HTML/CSS，其余格式返回友好提示（非崩溃）。
