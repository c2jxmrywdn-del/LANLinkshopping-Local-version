## 三、核心业务规则（实现与测试对齐）

### 3.1 运费计算（LogisticsFreightCalculator）

```
计费重 = max(实际重量kg, 体积重量kg)；体积重量 = 长×宽×高(cm) / volumeFactor
运费 = 首重费 + ceil(max(0, 计费重 - 首重) / 续重单位) × 续重费 + 偏远附加 + 区域加价
满额包邮：订单金额 ≥ freeThreshold(>0) → 运费 = 0
fixed 计费 = 首重费；piece 计费 = 首重费 + max(0, 件数-1) × 续重费
计费快照落 freightCalcJson（留痕可审计）；负数运费钳位为 0
```

### 3.2 运单状态机（LogisticsStateMachine）

```
pending_ship → picked_up → in_transit → out_for_delivery → delivered
in_transit/out_for_delivery → exception；exception → in_transit | returned | lost
终态（delivered/returned/lost/cancelled）不可再流转；同状态幂等放行
```

### 3.3 幂等保证

| 场景 | 机制 |
|------|------|
| 轨迹重复同步 | `UNIQUE(waybill_id, trace_time, status, description)` + 先查后插 |
| 异常告警 | 同运单同类型未处理告警存在时不重复创建 |
| 结算单生成 | 同服务商同账期已存在非作废结算单 → 拒绝 |
| 状态流转 | 同状态幂等返回（不报错） |

## 四、扩展指南

### 4.1 对接真实物流服务商 API

`LogisticsTraceParser` 已预留统一入口。扩展步骤：

1. 在 `t_logistics_provider` 配置 `api_type=api` + `api_endpoint` + `api_key`；
2. 新建 `LogisticsProviderClient` 接口（拉取轨迹）→ 各服务商实现类；
3. 在 `LogisticsWaybillService.syncTrace()` 改为从 ProviderClient 拉取节点列表（接口签名不变）；
4. 沙箱/mock 模式（`api_type=mock`）继续用 `/logistics/trace/sync/{waybillId}` 手工/模拟推送。

### 4.2 新增结算维度

`t_logistics_settlement` 按服务商+账期聚合；如需按仓库/线路维度，扩展 `generate()` 查询条件 + 补充 `warehouse_id` 列（幂等 ALTER 模式见 schema.sql）。

### 4.3 权限模型

| 操作 | 权限标识 | 说明 |
|------|---------|------|
| 商家发货/状态流转 | `merchant:manage`（`@RequirePerm`） | 商户身份自动具备 |
| 运营后台全套 | `admin:all`（通配） | 平台运营 |
| 运单/轨迹查询 | 登录即可 | 服务层可加归属校验扩展买家只看本人运单 |

## 六、常见问题

**Q: 发货报"订单不在待发货状态"？**
A: 检查 `t_order.order_status`（需 0=待发货）且 `pay_status=1`（已支付）。

**Q: 运费与预期不符？**
A: 查运单 `freight_calc_json` 计费快照（含 pricingType/chargeableWeight/regionSurcharge 等明细），逐项核对公式。

**Q: 轨迹同步没生效？**
A: 检查节点 `description` 是否含可识别关键词（揽收/运输/派件/签收/拒收/退回等），未知描述默认按 `in_transit` 处理。

**Q: 结算单生成报"已存在结算单"？**
A: 幂等保护，同服务商同账期只允许一张。如需重新生成，先逻辑删除旧单（`deleted=1`）。
