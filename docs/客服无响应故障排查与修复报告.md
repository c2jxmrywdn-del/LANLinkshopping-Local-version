# 客服无响应故障排查与修复报告

> 故障日期：2026-10-15 ｜ 修复完成：2026-10-15 ｜ 影响范围：网站客服问答（`/api/support/ask`）在局域网 IP 访问下全部无响应

## 一、故障现象

用户通过局域网地址 `http://192.168.231.42:5174` 访问前端，在"专属客服"窗口提问（如"如何注册账号？"）后，客服始终回复：

> 客服暂时无法响应，请稍后重试。

而知识库实际收录了该问题（`account-registration` 条目），应返回具体注册指引。前端无 JS 报错，页面其他功能正常。

### 3. 分层定位（逐层注入请求取证）

## 三、根因（双因叠加）

### 根因 1：可信代理签名头缺失（后端 403）

后端 `SupportController` 要求可信代理注入两个头：
- `X-Support-Proxy-Secret`（与 `support.proxy-secret` 比对）
- `X-Support-Client-IP`（限流键）

生产环境由 Vercel 代理函数（`frontend/api/support/ask.js`）注入，**本地 Vite 代理不注入**，且 dev 配置未定义 `support.proxy-secret`（空密钥 fail-closed）→ 所有请求被 403 拒绝。前端对非 2xx 统一显示"客服暂时无法响应"，掩盖了真实原因。

### 根因 2：局域网 IP 被 CORS 白名单拦截（用户实际访问路径）

用户经 `http://192.168.231.42:517x` 访问，浏览器携带 `Origin: http://192.168.231.42:517x`；后端 CORS 白名单仅 `http://localhost:*`、`http://127.0.0.1:*` → Spring CORS 过滤器返回 `Invalid CORS request`（403）。此问题独立于客服接口，会影响所有经局域网 IP 的写接口（登录/注册等）。

### 伴随问题

- **5174 端口残留旧 dev 实例**：加载的是修复前配置，用户截图恰访问 5174，即使 5173 修复也仍失败；
- **知识库关键词缺口**："怎么下单"未被 `order-navigation` 关键词覆盖（仅"如何下单/下单流程"）；
- **前端误导文案**：后端明确拒答文案被丢弃，统一显示"无法响应"。

### 5.4 监控机制验证

后端日志实证：

```
INFO  [support-monitor] proxy-secret configured (length=43), trusted-proxy auth enabled   ← 启动自检通过
```

## 六、结论

客服无响应由**双根因叠加**导致（可信代理签名头缺失 + 局域网 IP 被 CORS 拦截），叠加旧配置残留实例（5174）放大了影响面。现已完成全部修复与加固：局域网 IP 通道 8/8 问答全通（平均 25ms）、异常监控告警就位、回归测试全绿。用户现可通过 `http://192.168.231.42:5173` 正常使用客服功能。
