## 2. 需求 1：敏感字段后端独立校验

| 敏感字段 | 后端策略（不信任前端） | 位置 |
| --- | --- | --- |
| 商品价格 / 订单金额 | 服务端按商品当前价**权威重算**（`p.getPrice() × quantity` 累计，促销/会员折扣由 PricingFacade 编排），前端传值不参与计算 | `OrderService.doCheckout` |
| 积分抵扣金额 | `MembershipService.redeemPoints` 服务端按规则钳制重算（1000 积分 = 1 元、整元、单笔上限） | `OrderService.doCheckout` |
| 支付方式 | 白名单 `balance/corporate/term`，白名单外拒绝 + **告警** | `OrderService.doCheckout` |
| 积分数 | `usePoints < 0` 拒绝 + **告警** | `OrderService.doCheckout` |
| 支付状态 | 状态机原子流转 `markPaidAtomic`（仅 `pay_status=0` 可推进），前端不可指定目标状态 | `OrderMapper.markPaidAtomic` |
| 退款状态 | 状态机原子流转 `applyRefundAtomic`（仅 `none/rejected` 可申请），前端不可指定目标状态 | `OrderMapper.applyRefundAtomic` |
| 库存数量 | 原子扣减 `UPDATE ... WHERE stock >= quantity`，0 行拒绝（并发防超卖） | `ProductMapper.deductStockAtomic` |
| 退款可退余额 | 服务端按 `totalAmount - 已退` 计算钳制，超额拒绝 | `PaymentService.refund` |

## 3. 需求 2：幂等性校验与并发控制

| 机制 | 实现 | 覆盖接口 |
| --- | --- | --- |
| 幂等令牌 | `t_idempotent_token` 表 `UNIQUE KEY(biz_type, biz_key)` + `IdempotentService.reserve/bound/release`，重复提交抛"请勿重复提交"；失败释放允许携带同一 key 重试 | `checkout`（前端 `idempotentKey`：失败重试复用、成功重置） |
| 状态机原子流转 | `markPaidAtomic`、`applyRefundAtomic` 条件更新（影响行数 0 即并发冲突拒绝） | 支付、退款申请 |
| 库存原子扣减/回滚 | `deductStockAtomic`（`WHERE stock >= quantity`）、`restoreStockAtomic`（销量 `GREATEST(0,...)` 钳位） | 下单、取消/退款回滚 |
| 账单行锁 | `selectForUpdate` | 账期还款 |

> 说明：项目无 Redis 依赖，分布式锁语义由数据库唯一约束令牌表等价实现——多实例并发下同一 `(bizType, bizKey)` 仅一个事务插入成功，其余被唯一键冲突拦截。

## 4. 需求 3：前后端校验规则同步维护机制

- **契约权威源**：`backend/src/main/java/com/lanlink/shopping/common/ValidationRules.java`
- **前端镜像**：`frontend/src/utils/validationRules.js`（同名常量 + `validateCheckoutForm` 同口径校验）
- **消费点**：`CheckoutDTO`（`@Size` 引用契约常量）、`OrderService`（白名单引用契约常量）、`Checkout.vue`（提交前形式校验）
- **契约文档**：`docs/数据校验规则契约.md`（规则明细表 + 变更同步流程）
- **同步守护测试**：`TamperAttackSimulationTest#frontendBackendValidationRulesInSync` 自动断言前后端白名单集合与长度上限一致，任一侧改规则未同步会**测试失败**。

## 5. 需求 4：篡改告警与日志追溯

- 落库 `t_tamper_alert`：用户、业务类型、字段名、客户端值、服务端值、原因、客户端 IP（含 X-Forwarded-For 解析）、User-Agent、时间
- 结构化日志：`[tamper-alert]` WARN（运行实测日志可见全部 5 类攻击字段告警）
- 审计链：`AuditService` 记录 `TAMPER_ALERT` 动作，全链路可追溯
- 触发点：非法支付方式、负积分、支付/退款状态机并发拒绝、金额一致性比对失败（`checkNumeric/checkStatus`）
